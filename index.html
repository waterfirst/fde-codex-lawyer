Why · FDE 관점

코드를 가르치지 않는다. "AI에게 일 시키는 법"을 이식한다.

FDE(Forward Deployed Engineer)는 고객 현장에 들어가 실제 업무를 이해하고, 짧은 시간에 돌아가는 맞춤 솔루션을 함께 만든다. 이번 실습의 고객은 개인파산·개인회생 변호사다.

고객의 실제 업무

사건 접수, 자료정리, 누락자료 확인, 쟁점 후보 탐지, 보고서 초안, 변호사 검토 질문 정리.

도구

Python이 변호사 노트북 안에서 문서를 읽고 마스킹한다. Codex가 파일과 루틴을 만들고, 법제처 MCP가 실제 법령 근거를 붙인다.

성공 기준

2시간 뒤 변호사가 혼자서 익명 사건 1건의 1차 검토 패킷을 재실행할 수 있으면 성공.

Tool Split · 도구 분업

Python은 로컬 눈, Codex는 손, 법제처 MCP는 근거

변호사 업무는 문서 독해가 핵심이다. 그래서 처음부터 한 도구로 다 하지 않고, 일마다 제일 잘하는 AI에게 맡긴다.

Python local reader · 눈

변호사 노트북 안에서 문서 텍스트, 날짜, 금액, 문서목록을 추출하고 개인정보를 마스킹한다.

Local API · 문서 처리

PDF/OCR/표 추출은 Python 라이브러리나 로컬 API로 처리한다. 외부 전송 전 마스킹 결과를 확인한다.

Codex · 손

마스킹 JSON/Markdown을 받아 파일 구조, 체크리스트, HTML 패킷, 반복 루틴으로 만든다.

법제처 MCP · 근거

기억으로 법을 쓰지 않고 실제 법령 조문을 확인한다. 환각을 줄이는 기준점이다.

Claude/GPT · 오케스트레이터

목표, 입력, 출력, 제약, 단계, 종료조건을 정하고 각 워커 결과를 검토한다.

변호사 · 최종 판단

AI는 초안과 정리만 한다. 법률 판단, 전략 선택, 의뢰인 커뮤니케이션은 변호사가 책임진다.

🔐 개인정보 안전선

실제 사건 문서는 변호사 노트북 밖으로 나가지 않는다. NotebookLM/Gemini는 익명 샘플 또는 완전 마스킹 자료에 한해 선택적으로만 쓴다.

Solution · 토탈 솔루션 구성

다섯 개의 루틴 = 사건 1건의 1차 검토

각 루틴은 입력 → 정리 → 법제처 MCP 근거 확인 → 초안 → 변호사 검토 구조. 법률판단은 사람이 한다.

① 법령 Q&A

의뢰인 질문 → 관련 법령 자동 검색 → 조문 인용 + 평이한 설명. "이 상황에 어떤 법이 적용되나?"를 즉답.

② 개정 모니터

관심 법령(예: 개인정보보호법)의 변경 감지 → 변경점 요약 리포트. 매주 자동으로 "무엇이 바뀌었나"를 받는다.

③ 자문 메모 생성

사안 입력 → 관련 법령·판례 근거 수집 → 자문 메모 초안(HTML). 변호사가 검토·수정만.

④ 사건 Intake

원본자료 → 문서 인덱스 → 누락자료 → 기본 사실 요약. 사건 시작 30분을 줄이는 루틴.

⑤ 검토 패킷

쟁점 후보, 법령 근거, 증빙표, 변호사 질문을 한 화면에 모아 최종 검토 시간을 줄인다.

⚖ 안전 원칙 (변호사에게 반드시 심을 것)

AI 출력은 초안이지 법률 자문이 아니다. 모든 결론은 인용된 조문·판례로 검증한 뒤 변호사가 최종 책임진다. 의뢰인 실명·민감정보는 넣지 않는다.

Orchestration · 일하는 구조

단일 답변이 아니라 워커를 나눠 일한다

이게 이번 실습의 핵심이다. 변호사 업무를 한 번에 묻지 말고, 작은 워커들에게 나눠서 맡긴다.

Intake Worker

파일명, 문서유형, 누락자료, 사건 기본정보를 정리한다.

Extraction Worker

PDF/OCR 텍스트에서 날짜, 금액, 계좌, 재산, 소득, 가족관계 후보를 뽑는다.

Screening Worker

가족 간 이체, 편파변제, 재산처분, 보험, 차량, 진술불일치 후보를 표시한다.

Legal Grounding

법제처 MCP로 관련 법령 조문을 확인한다. 기억으로 조문을 만들지 않는다.

Evidence Worker

주요 문장마다 문서명과 페이지 근거를 붙이고, 근거 없는 문장은 분리한다.

Review Worker

개인정보 노출, 법률 단정 표현, 누락자료, 변호사 질문을 최종 점검한다.

Setup · 법제처 MCP 연결

변호사가 따라 하는 MCP 연결법

MCP는 AI에게 “법제처 검색도구”를 붙여주는 연결장치다. Codex가 기억으로 법을 말하지 않고, 법제처 조문을 직접 확인하게 만든다.

  1. 인증키 발급 — open.law.go.kr에서 오픈API 신청 → 본인 OC(이메일 앞부분 형태) 발급.
  2. 변호사 노트북에서 Codex/Python 확인 — 사건 문서는 노트북 안에서만 읽고, Codex는 마스킹 결과와 법령 조회만 수행한다.
  3. Codex에 MCP 등록 — ~/.codex/config.toml에 아래 블록 추가(본인 키로).
  4. 연결 확인 — Codex에서 "채무자 회생 및 파산에 관한 법률에서 개인파산 관련 조문 찾아줘" → 실제 조문이 나오면 성공.
[mcp_servers.korean_law]
command = "npx"
args = ["-y", "korean-law-mcp"]
env = { LAW_OC = "본인_인증키" }
startup_timeout_sec = 30
tool_timeout_sec = 180
enabled = true

변호사에게 각인시킬 한 줄

법률 판단을 AI에게 맡기는 게 아니라, 법률 검토 전 자료정리와 조문확인을 자동화하는 것이다.

왜 GitHub인가

변호사에게 "결과를 자산으로 남기는 습관"을 심는다. 사내 서버·설치 없이 링크 하나로 공유·재실행. FDE의 마지막 1cm = 핸드오프.

Principles · 변호사에게 심을 5가지

2시간 뒤에도 남을 원칙

1. 코드가 아니라 지시

배우는 건 프로그래밍이 아니라 명확히 지시하는 법. 목적·입력·출력·제약을 문장으로.

2. 규칙은 한 번만

반복 규칙은 AGENTS.md에, 반복 절차는 SKILL.md에. 매번 설명하지 않는다.

3. 근거 없으면 안 쓴다

모든 답은 조문·판례 인용 필수. 인용 못 하면 "모른다"로. 환각 차단.

4. 토큰은 아껴 쓴다

필요한 조문만. 긴 문서 통째로 넣지 않기. 요약본으로 대화.

5. 사람이 최종 책임

AI는 초안 생성기. 검토·판단·책임은 변호사. 이 선을 처음부터 분명히 한다.
